# claude_change_spec.md: UX fix build (U1)

Base: GitHub `main` at `762fd14` (11 Nov 2026, plans and trial). Everything here is web-side. Do not touch `android/`, `capacitor.config.ts`, or anything under `mobile-shell/`. No APK change.

## 1. Context and goal

An app review found seams between the engine and the shell: developer tools exposed to every user, a first chat interrupted by two sheets, a send path that loses text, a single-line composer, stacked reply latency, unbounded history loads, and stale copy. This build fixes the approved subset. It adds no new product surface beyond a fuller profile, a pinned-messages list and a web manifest.

Rules that hold for the whole build:

- Every user-facing string lives in `src/lib/copy.ts`. No em dashes and no exclamation marks in any new or moved string.
- Level numbers are never shown. Stage is shown by name only.
- Core names are never shown.
- The plan bars in `Composer.tsx` (`trialLimit`, `expired`, `locked`, `fairUse`, `oneLeft`) and everything in `src/lib/entitlement.ts`, `src/lib/plans.ts`, `src/lib/billing.ts` and `app/plans/` stay as they are.
- Honour `prefers-reduced-motion` for every new animation.

## 3. Database migration `20261115000001_ux_fixes.sql`

Follow the conventions of `20261111000001_plans_and_trial.sql`: `security definer`, `set search_path = ''`, `ally_private.require_uid()`, `ally_private.own_companion(...)`, explicit grants to `authenticated`, revoke from `anon` and `public`.

1. **`get_my_state` paging.** Redefine from the 11 Nov version. `messages_by_companion` returns only the newest 50 rows per companion (still ordered oldest to newest). Add `has_more_by_companion`: a jsonb object of companion id to boolean, true when older rows exist. Nothing else in the payload changes.
2. **`get_messages_before(companion_id text, before_id bigint, limit_n int default 50)`.** Owner only. Returns `{ messages: [...], hasMore: boolean }` using `ally_private.message_json`, oldest to newest, rows with `id < before_id`. Clamp `limit_n` to 1..100.
3. **`get_pinned_messages(companion_id text)`.** Owner only. Her non-deleted messages where `meta->>'effect' = 'pin'`, newest first, max 50, as `message_json`.
4. **`delete_memory_fact(fact_id bigint)`.** Hard delete of one `memory_facts` row owned by the caller. Idempotent: returns `{ deleted: boolean }`. No tombstone, no block list. Allowed for locked and expired companions.
5. **`retract_reply(companion_id text, message_id bigint)`.** For edit regeneration. In one transaction, with the companion row locked:
   - `message_id` must be the caller's own, non-deleted, `who = 'me'`, with `edited_at` not null, and the newest `who = 'me'` row in the chat.
   - Every row with a higher id must be `who = 'them'` with `in_reply_to = message_id`. If any other row follows, raise `not_latest`.
   - The companion must be active, not paused, and the caller's entitlement must allow sending to it (not expired, not outside the slot limit). Otherwise raise `not_allowed`.
   - Hard delete those reply rows. Remove `reaction` from the user message's `meta` and set `meta.regen = true`.
   - Set `companions.last_replied_msg = message_id - 1` so the reply route's claim (`last_replied_msg < message_id`) succeeds again.
   - Returns `{ removedIds: bigint[], message: message_json }`.
   - No ledger debit, no fair-use count, no trust change.
6. **`export_my_data()`.** Owner only. Returns profile, consents, companions, all messages (deleted ones as tombstones without text), `memory_facts`, `memory_summaries`, and the entitlement as `get_my_state` reports it (plan and trial dates). Never returns hidden fair-use caps, trust points, `safety_events` or admin fields.

## 4. Steps

### P0-2. QA-gate developer tools and forced pings

- `app/api/chat/ping/route.ts`: when the caller is not cron, honour `force` only if `supabase.rpc("is_qa")` returns true. For anyone else treat `force` as false (do not 403; the normal checks then apply). Cron behaviour is unchanged.
- `app/settings/notifications/page.tsx`: render "Test Ping", "Test Midday Reminder" and "Test Evening Reminder" only when `useQaAccess(auth.user?.id).qa` is true. For other users the block is not in the DOM.

### P0-3. First-chat interruptions

Consent:

- `config.ts`: `CONSENT_VERSION = "2026-11-v2"`. Keep `LIVE_CONSENT_VERSION = "v2-live-groq"` as a legacy accepted value. Add `LIVE_OK_VERSIONS = [CONSENT_VERSION, LIVE_CONSENT_VERSION]`.
- `app/onboarding/consent/page.tsx`: add `COPY.consent.live` as a paragraph above the checkboxes. After the consent insert succeeds, also dispatch `SET_CONSENT_VERSION` with `CONSENT_VERSION`, so a fresh user never sees the chat sheet.
- `app/chat/[id]/page.tsx`: `needsConsent = live && !LIVE_OK_VERSIONS.includes(state.user.consentVersion ?? "")`. `onConsentContinue` inserts `CONSENT_VERSION`.
- `ConsentUpdateSheet`: reworded copy (section 4, copy table). Shown only to existing users whose newest consent is the September version.

Account sheet timing:

- Remove the exchange-1 nudge.
- Open the sheet at exchange 3 (dismissible) and 7 (blocking) only once her reply to that exchange has landed: `companion.exchanges >= n`, the last message is `who = 'them'`, `typing` is false and no reply is playing. For a mock companion the same rule applies after `receiveReply` resolves.
- Keep `accountNudgeRef` so each threshold fires once per mount.

### P1-6. Optimistic send

- `Composer.submit` no longer clears the text itself. `onSend(text)` returns `Promise<boolean>`; the composer clears optimistically and restores the text if it resolves false and the box is still empty.
- `handleSend`: insert a local pending bubble immediately (negative temp id, `pending: true` on `Message`, client only). On success replace it with the server message via a new reducer action `CONFIRM_SENT { companionId, tempId, message, exchanges, ledger, entitlement }`. On failure or a server refusal (`blocked`), remove it with `DROP_PENDING` and return false. A refusal still dispatches `LEDGER_SYNC` as today.
- A pending bubble renders at 60% opacity, has no actions and no receipt. `isSaved()` already excludes negative ids.
- If the user sends again while one is pending, sends go out in order (await the previous).

### P1-7. Composer

- Replace the `<input>` with a `<textarea rows={1}>` that grows to 5 lines, then scrolls. Same visual style. Keep `aria-label="Message"`.
- Desktop (`matchMedia("(pointer: fine)")`): Enter sends, Shift+Enter inserts a line break. Touch: Enter inserts a line break; only the send button sends.
- Messages keep their line breaks: `white-space: pre-wrap` on bubble text, quote previews stay single line with ellipsis.
- Draft per companion in `localStorage` key `ally_draft:<uid>:<companionId>`, written on change (debounced 300 ms), cleared on successful send, restored on mount. Not used while editing. Wrap storage in try/catch.
- Plan bars and the `fairUse` notice are untouched.

### P1-8 and P1-9. Latency and read receipt

`src/lib/readDelay.ts` (pure, unit tested):

- `readDelayMs(tier, rand)`: `free` 1000..2000, `busy` 3000..5000, `asleep` 6000..8000.
- `tierFor(heartNow)`: `asleep` when the block row is -1. `busy` when the block's energy word (persona `engine.energy[presence]`) is one of a `BUSY_ENERGY` set. Seed the set with `busy`, `focused`, `distracted`, then read all 32 persona files and add whatever energy words describe a work, class or commute block. Everything else is `free`. Mock companions are always `free`.

Chat page:

- On send: start the reply request immediately, in parallel with the read delay. Do not show typing dots yet.
- Add explicit `readUpTo` state (message id). The receipt shows "Delivered" until the read delay elapses, then "Read", then the dots. Change `receiptFor` to take `readUpTo` instead of inferring from `typing`. A reply that has landed always counts as read.
- First bubble typing time = `max(600, typingMs(len) - max(0, elapsedSinceRequest - readDelay))`. Later bubbles keep `typingMs` unchanged. The `stop` effect timing is unchanged.
- The tapback still appears 700 ms after the message is marked read, not before.
- Queued follow-ups (`queuedRef`) use the `free` tier.

### P1-10. History paging

- `schema.ts`: `Companion.hasMore?: boolean`. `assembleServerState` reads `has_more_by_companion`.
- `queries.ts`: `getMessagesBefore(companionId, beforeId)`.
- Reducer: `PREPEND_MESSAGES { companionId, messages, hasMore }`, de-duplicated by id.
- `MessageList`: an `IntersectionObserver` sentinel at the top loads the previous page when `hasMore`. Preserve scroll position on prepend (measure `scrollHeight` before and after). Show a small inline loader row, no spinner overlay.
- Quote jump: if the original is not loaded, page backwards until it is found (max 10 pages), then jump and flash. If not found, toast `COPY.chat.messageGone`.
- Check everything that assumed a full list: the "Since you left" divider, `receiptFor`, the home card's last message, `isFirstOpenEver`, the opener seed (`messages.length === 0` must still mean an empty chat: use `messages.length === 0 && !hasMore`).
- Locked and expired companions page normally.

### P1-11. Chat list

- Date separators between messages on different local days: "Today", "Yesterday", else `Mon 9 Nov` (add the year when it is not the current year). Helpers in `src/lib/chatDates.ts`, pure, `now` passed in.
- Tap a bubble to toggle its time (`9:41 pm`) under it. A tap is a pointer up with under 10 px movement and no long-press fired; add it to `useBubbleGestures` so it never conflicts with swipe or long-press. One open at a time.
- Auto-scroll to the end only when the user is within 120 px of the bottom, or when the new message is their own.
- `JumpToLatest`: a round button above the composer when scrolled more than 300 px from the bottom. It shows a dot when a message arrived while scrolled up. Tap scrolls to the end.

### P2-14. Profile

Below the header video, above the toggles:

- Bio: `{city}`, `{occupation}`, then the template's `read` line.
- Stage (live companions only): label `COPY.profile.stage`, value `persona.levels[trustLevel - 1].name`. If the plan caps the level, show the capped level's name. Never a number or a progress bar.
- `MemoryList`: heading `COPY.profile.remembers` with the persona's first name. ### P2-19. Smaller gaps

Pinned messages:

- `PinnedSheet` lists `get_pinned_messages` results (text, date). Tapping one closes the sheet and jumps to it using the quote-jump path from P1-10. Empty state: `COPY.chat.pinsEmpty`.

Edit regenerates her reply:

- After `editMessage` succeeds on a live companion, regenerate only if all hold: the edited message is the newest `me` message, every later message is hers with `inReplyTo` equal to it, no reply is playing, and the companion is not locked and the plan is not expired.
- Then call `retract_reply`, remove the returned ids with a new `REMOVE_MESSAGES` action, apply the returned user message, and call `fetchAndPlay(companionId, "reply", messageId)`.
- If `retract_reply` raises `not_latest` or `not_allowed`, keep the edit and do nothing else.
- `app/api/chat/reply/route.ts`: when the answered user message has `meta.regen === true`, skip trust scoring for this reply (pass `trust: null`, `day: null` to `write_live_reply` and return the unchanged level), skip the 100-message milestone, and clear `meta.regen` in the same write. Effects, safety and lint run as normal.
- Mock companions never regenerate.

Web manifest and service worker:

- `ServiceWorkerRegister`: registers `/sw.js` in production only, and never when `Capacitor.isNativePlatform()` is true. Mount it in `app/layout.tsx`.
- Confirm `middleware.ts` does not redirect `/manifest.webmanifest`, `/sw.js` or `/icons/*`; extend the matcher exclusions if needed.

## 5. Tests

Unit (vitest):

- `readDelay.test.ts`: ranges per tier; every block of all 32 personas resolves to a tier; asleep row maps to `asleep`.
- `chatDates.test.ts`: Today, Yesterday, same year, other year, midnight boundary.
- `onColor.test.ts`: all 32 manifest palettes reach at least 4.5:1 with the chosen text colour.
- `chatActions.test.ts`: `receiptFor` with `readUpTo`; pending bubbles have no actions.
- `allyReducer.test.ts`: `CONFIRM_SENT`, `DROP_PENDING`, `PREPEND_MESSAGES` (de-dup), `REMOVE_MESSAGES`.
- `copy.test.ts`: no em dash or exclamation mark in any `COPY` string; new keys present.

RLS (`npm run test:rls`):

- `get_my_state` returns at most 50 per companion and a correct `has_more`.
- `get_messages_before`, `get_pinned_messages`, `delete_memory_fact`, `export_my_data`: owner succeeds, another user gets nothing or an error, anon is refused.
- `retract_reply`: happy path; `not_latest` when a newer user message exists; refused for an unedited message; refused for a locked or expired companion; no ledger or trust change.
- `export_my_data` never contains fair-use caps or trust points.

E2E (Playwright), new `e32-ux-fixes.spec.ts` plus updates to existing specs:

- Non-QA user sees no Test buttons; `POST /api/chat/ping` with `force: true` from a non-QA user does not ping a companion that was active a minute ago.
- Fresh onboarding reaches the first chat with no consent sheet; an existing user on the September consent sees the reworded sheet once.
- Account sheet does not open after exchange 1; opens after her third reply lands.
- Failed send (mock the RPC to fail) restores the text; successful send shows the bubble before the RPC resolves.
- Multiline message keeps its line break; draft survives a reload.
- "Delivered" is visible before "Read".
- A chat with 120 seeded messages shows 50, loads more on scroll up, keeps position, and a quote to an unloaded message jumps to it.
- Date separator and tap-for-time render; jump pill appears and works.
- Profile shows bio, stage name and facts; deleting a fact removes it and it stays gone after reload.
- Overflow menu items; scrim tap closes the switcher but not the blocking account sheet.
- Edit of the newest answered message replaces her reply; edit of an older message does not.
- `/manifest.webmanifest` and `/sw.js` return 200 without a session.

Regenerate `tests/e2e/__screens__` for every changed screen. Update existing specs that asserted the old behaviour (exchange-1 account sheet in `e1`, `e15`; overflow Home in `e9`, `e10`; consent sheet in `e28`; receipts in `e28`, `e30`).

## 7. Out of scope

Deck collapse for non-Romantic cores, the Terms page, FCM push and reminder behaviour, Android back handling, the boot splash hold, Google sign-in, user tapbacks, anything in plans or billing.

## 8. Known edge, accepted

A fact deleted on the same day it was mentioned can be re-extracted by that night's vault run, because the source messages still exist. That matches "she can relearn it" and is left as is.
